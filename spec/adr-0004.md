# ADR 0004: optional ROCm device-resident sequential inference

Status: experimental; GPU execution/performance unverified until the opt-in suite
passes on RX 7900 XTX / WSL2. CPU reference remains the correctness oracle.

Rust owns immutable uploaded weights, per-run device state, reusable scratch,
and token IDs separately. A narrow versioned C ABI owns HIP allocations, one
stream and a rocBLAS handle. Rust loads an explicitly supplied local shared
library; no download, Python, or automatic CPU fallback. This avoids requiring
ROCm to compile/test the Rust package. `rocm` is a Linux-only optional feature.
A separately built CPU test bridge executes the same kernel bodies; it is
rejected by production loading and is NOT evidence of GPU correctness.

All language weights are uploaded once as FP32, retaining [out,in] row-major
layout. rocBLAS sees these bytes as [in,out] column-major and uses transpose
GEMV. Embedding and vocabulary projection share one device allocation. KV is
preallocated to an explicit short context capacity; DeltaNet convolution and
recurrent state have fixed size. No host/device roundtrip inside a layer.
Normal inference downloads only full logits per token (CPU greedy selection).
Optional capture downloads layer boundaries, norm and state for validation.
Sequential prefill deliberately uses the same step as decode; GEMM prefill,
parallel reductions, kernel fusion, BF16, GPU sampling and persistent chat
snapshots are not implemented in this first GPU backend.

Kernel bodies follow existing Rust equations, not a high-level model runtime.
Norm/attention use simple per-head loops to preserve readability. They are a
correctness-first starting point, not a claim of optimized throughput. Native
FFI status, launch status, synchronization and finite downloaded results are
checked. A failed stateful step poisons its run until reset. Out-of-range IDs
and capacity errors are rejected before enqueueing any work.

Acceptance order (frozen before implementation):
1. Build/tests without feature stay offline and ROCm-independent.
2. CPU bridge: non-square GEMV, full hybrid fixture layer boundaries/logits,
   all mixer state, split prefill, reset, independent runs and input rejection.
   Existing tiny atol=2e-5, rtol=2e-4; do not relax for failures.
3. Real HIP bridge: same tiny suite; optional real-model layer/logit/state
   comparison against CPU at atol=rtol=3e-3, as used by existing real validation.
4. Time GPU work only after stream completion. Report loading/upload separately;
   validation copies are excluded from inference timing. No speed assertion.

AMD stack must follow a single versioned official WSL support matrix (7900 XTX
is listed, e.g. ROCm 7.2). Never install a native Linux kernel driver in WSL.
See spec/rocm.md for build/validation commands and environment provenance.
ADR 0005 later generalized the Rust side to `src/device.rs` for a Metal bridge.

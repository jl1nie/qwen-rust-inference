# ADR 0022: load the MTP head for measurement; greedy acceptance on CPU

Status: accepted (measurement only; no speculative decoding yet).
See spec/measurements/mtp-acceptance-cpu.json and spec/roadmap.md item 3.

## Context

The checkpoint has one MTP (multi-token prediction) block (`mtp.*`, 15
tensors, 41 MB) that the text model skips (spec/ignored-tensors.json). Before
building speculative decoding on it (spec/roadmap.md, item 3), we need to know
how often its drafts match the main model's greedy tokens on this 0.8B model.
llama.cpp (Qwen3.6, 3 drafts, ~75 %) and Strata (Qwen3.8-Flash-Next,
0.89/0.86/0.85) report their own numbers on larger models
(spec/other-engines.md).

## Decision

- `weights::load_mtp` reads only `mtp.*` in a second pass over the same
  SHA-256-checked file. `load_model`, the model identity and saved snapshots
  are unchanged.
- `src/mtp.rs` computes the head, as in llama.cpp's `graph_mtp`
  (`src/models/qwen35.cpp`):
  - input: the main model's final-normalized hidden state h_i (the input of
    the vocabulary projection) and the embedding of s_{i+1};
  - `fc([RMSNorm(embed), RMSNorm(h)])` (2048 -> 1024), one attention block of
    the main model's shape with its own KV cache, `mtp.norm`, then the tied
    embedding as the vocabulary projection;
  - all four norms are zero-centered (1 + w), like the main model's; the
    weights have the same statistics as the main norms (`mtp.norm` mean 3.44
    vs `norm` 3.31);
  - a second draft feeds the head its own normalized output and its first
    draft; those KV rows are then truncated.
- `Model::step_hidden` returns the hidden state with the logits
  (`step_compact` now calls it; same values).
- `mtp-accept` generates each prompt greedily with the main model. At every
  generated position i the head drafts `--depth` tokens from (h_i, s_{i+1}).
  Draft j counts as accepted when drafts 1..j all equal the greedy tokens.
  That is what greedy speculative decoding would accept, so the expected
  tokens per verify pass with k drafts is 1 + sum_{j<=k} P(accepted to j).
- `tests/mtp.rs` checks the mechanics on the synthetic fixture: chaining and
  truncating leaves the next true step bitwise identical, and `step_hidden`
  equals `step`.

## Consequences

M5 CPU, 8 prompts (Japanese and English; explanation, code, translation,
arithmetic, story; spec/measurements/mtp-prompts.txt), up to 128 greedy
tokens each, 851 drafting positions:

| | draft 1 | draft 2 | draft 3 |
|---|---|---|---|
| accepted up to j | 68.4 % | 43.2 % | 26.8 % |
| given the previous one accepted | 68.4 % | 63.1 % | 62.1 % |
| tokens per verify pass (k drafts) | 1.68 | 2.12 | 2.38 |

By prompt, draft 1 ranges from 50.7 % (English story) to 85.8 % (Python
code, where drafts 1-3 give 0.86/0.71/0.53). On the prompt text itself
(teacher forcing) the head predicts the token after next 48.5 % of the time.
The rates are lower than the reports for larger models above, as expected for
a 0.8B model, but the head clearly works: a wrongly wired head would be near
0 %.

Cost. On CPU a head step takes 5.0 ms against 26.1 ms for a main step. On a
bandwidth-bound GPU decode the head reads its 41 MB plus the 509 MB
vocabulary projection, about 0.37 of a main step (1.50 GB). If a verify pass
of k+1 tokens costs about one main step, the estimate is 1.68/1.37 = 1.23x
(k=1), 2.12/1.73 = 1.22x (k=2) and 2.38/2.10 = 1.13x (k=3). The vocabulary
projection dominates the draft cost on this small model. Drafting over a
subset of the vocabulary would keep the output unchanged (the main model
still verifies every token) and could raise the estimate towards 1.5-2x, at
some loss of acceptance. These are estimates, not measurements.

Not done: speculative decoding itself (verify pass, DeltaNet state rollback),
sampling (only greedy acceptance is measured), thinking mode, GPU engines.

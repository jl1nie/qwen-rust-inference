# ADR 0005: optional Metal bridge for Apple Silicon

Status: experimental; tiny fixture and real-model comparisons passed on Apple M5
(macOS 27.3). See spec/measurements/metal-m5.json. CPU reference remains the
correctness oracle.

ADR 0004's device engine is reused unchanged in shape: Rust owns immutable
uploaded weights, per-run state and scratch; a narrow versioned C ABI owns the
native resources. The former `src/rocm.rs` became `src/device.rs` and selects
the engine by `Kind` (CpuTest=0, Rocm=1, Metal=2) returned by `qr_kind`. A
library built for one engine, or the CPU test bridge, is rejected as another.
The Metal engine is a macOS-only optional feature `metal`; ROCm stays Linux-only.

`native/metal/bridge.mm` (Objective-C++, ARC) exports the same `qr_*` symbols.
Apple GPUs use unified memory, so each allocation is an `MTLStorageModeShared`
buffer and Rust receives its CPU `contents` address. The bridge keeps an
address-ordered map so interior pointers (embedding row lookup) resolve to
`(MTLBuffer, byte offset)` for `setBuffer:offset:`. Rust still never
dereferences device pointers; `qr_read`/`qr_write` wait for all queued work.

All kernels are encoded into one serial compute encoder and committed only at
a synchronization point (read, write, sync), which orders them like the single
HIP stream. Command-buffer errors are reported at that point, so a failed step
still poisons the run until reset. Device-to-device copy is a compute kernel
inside the same encoder.

`native/metal/kernels.metal` mirrors `body()` of the HIP/CPU bridge one kernel
per op, with the same one-thread-per-element/head/column decomposition. Buffer
slot i equals `Params.p[i]`; scalars are passed separately. GEMV is the only
reduction-parallel kernel: one 32-lane SIMD group per row of the row-major
Rust [out,in] matrix with `simd_sum`, so no transpose copy. Its summation order
differs from the CPU loop; the frozen ADR 0004 tolerances (tiny 2e-5/2e-4,
real 3e-3) apply unchanged. Kernels are compiled at runtime with
`MTLMathModeSafe` and precise math functions; this needs macOS 15+ but not the
Xcode `metal` shader compiler. MSL lacks log1p, so softplus uses log(1+e^x).

Long-context update (frozen tolerances unchanged):
- Device prefill computes the tied vocabulary projection and reads logits only
  at the last position of each prefill call; intermediate positions flush the
  queue every 32 steps. Shared by ROCm and Metal.
- The fixed 4096 capacity cap became the model context limit plus a 4 GiB
  per-run state budget (`MAX_RUN_BYTES`); default capacity is prompt+max new.
- Metal only: op AttentionRead is dispatched as three passes (scores per
  (position, head), threadgroup softmax per head, weighted V per (dim, head)).
  The C ABI and the HIP/CPU single-thread-per-head body are unchanged.
- `<engine>-check --text-file --tokens N` compares final logits, greedy top-1
  and ALL state against CPU `Backend::Vector` at boundaries around powers of
  two, in O(N) instead of the per-position capture's O(N^2).

Superseded in part by ADR 0006 (BF16 device matrices, chunked prefill, ABI v2).

Not implemented (same as ADR 0004): BF16/FP16, quantization, batched prefill,
fused kernels, GPU sampling, edits, traces, chat snapshots. FP32 weights exist
twice in unified memory (CPU model + device copy), roughly 2x 3.5 GB.

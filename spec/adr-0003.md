# ADR 0003: 単一ベクトル向けCPU演算、compact経路、状態の保存

状態: 採用。既存のスカラーループとmatrixmultiply sgemmは残し、単一バッチ用の
Backend::Vectorを通常推論へ採用する。8個の独立累積器で各行を直接読み、
行列のpackと全語彙sortを省く。浮動小数点の加算順序が変わるので、
既存の参照fixtureを変更せず、短い全演算と32/128/512位置を比較してから採用した。
全711位置・全KV/再帰状態、自然EOSが既存のatol=3e-3/rtol=3e-3で合格。
結果はvalidation-vector.json。行列自体の格納規約やモデル数式は変更しない。

Matrix内部をArc<Vec<f32>>にする。Vec→Arc<[f32]>は巨大配列のコピーを伴うため、
Vecの所有権を共有してロード時の一時コピーを避ける。外部へはsliceだけを返す。
Modelも公開fieldを読み取り専用getterへ移し、identity計算後の重み変更を防ぐ。
編集はこれまで通り別overlayで扱う。セッション/会話の保存は無編集モデルに限定する。

compact stepは同じblock演算を使い、層ごとに活性値を解放する。
DeltaNetの観測用stateコピーも省き、通常のinfer/session/chatで使う。
Full stepとtraceは全中間値を観測できる経路として維持し、bit単位の同値を試験する。

計測はmeasurements/cpu-baseline-vector.json。CPUはXeon 8573C、quota 2、release、
固定4入力ID・8decode・warmup 1回・測定2回。平均decodeは約1.23→2.64 token/s。
sgemm compact単体は速度向上を示していない。compactの目的は観測用メモリを減らすこと。
Vector採用後のピークRSSは約5.78→4.76GB、定常RSSは約3.07→3.04GB。
ピークはモデルのロードを含む生涯値で、推論フェーズのピークとは呼ばない。
速度は少数試行・一台の観測であり、他CPUや文脈で同じ倍率になるとは主張しない。

永続化には独自の小さいJSON header + little-endian f32 + SHA-256を使う。
既存safetensorsは重み読込み用として維持。状態はストリームで保存/復元し、
全payloadを別Vecへ複製しない。モデルidentity、backend、sampling/RNG、pending、
最後のlogits、live/anchorを揃えなければ正しく再開できないため、単なるKVファイルにはしない。
ファイル形式を変える場合はversionを更新し、未検証の互換性を仮定しない。

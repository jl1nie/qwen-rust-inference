# ADR 0031: device greedy picks in infer/chat; verify, absorb and draft chain linked on the device (Metal)

Status: accepted. See spec/measurements/metal-m5-greedy-fused.json and
ADR 0028 and 0030.

## Context

ADR 0030 added a device argmax (`step_greedy`, `verify_rollback_greedy`).
Two things remained:

1. `<engine>-infer` and `<engine>-chat` still read the full logits of every
   decode step and took the argmax on the host (about 0.3 ms per token).
2. In the speculative loop every MTP head forward ended in a sync, because
   the host needed an argmax before it could issue the next step. That was
   1 + k syncs per verify pass: the verify, the absorb of the accepted pairs,
   and the k - 1 chained drafts.

## Decision

Greedy decode in infer and chat:

- `generate::decode_greedy_ids` is greedy `decode_with` for an engine that
  returns the next ID itself, with the same stopping rules (unit test
  against `decode_with`). `<engine>-infer` uses it with `step_greedy`. A
  traced position still runs `step` with captures and picks from its logits.
- `DeviceChat` with greedy sampling feeds each generated token with
  `step_greedy` unless that position is observed. The logits that chose
  the pending token stay in the run's logits buffer
  (`DeviceRun::unread_logits`) and are read only when needed: an anchor, a
  snapshot (`to_session`), or sampling. `restore` / `load_state` drop them.
  Without `qr_argmax` (HIP, the CPU test bridge), `step_greedy` reads the
  logits on the host as before, and they are still in the buffer.

Verify, absorb and the draft chain linked on the device:

- Bridge op 17 `EmbedBf16Picked` (`embed_bf16_picked`, elementwise.metal)
  writes row picks[2r] of a BF16 matrix, so the next token of the head can
  come straight from a device argmax. `qr_argmax` returns 2 when it is
  present.
- `DeviceRun::verify_rollback_deferred` runs the verify pass and leaves the
  argmax of every row in `picks`, unread, with every row through the final
  norm in `norm`.
- `DeviceDraft::verify_absorb`: right after the verify, and without a sync,
  the head absorbs all t = k + 1 pairs (h_j, argmax_j). The hidden rows are
  copied from the main run's `norm` and the tokens embedded by
  `EmbedBf16Picked` from the main embedding. The head's argmax of every row
  is also deferred. Then one sync reads both sets of picks and the head's
  norm rows. `keep(m + 1)` rewinds the head's KV to the accepted pairs; the
  rows past them were computed from rejected tokens and are discarded. It
  also takes g and the first draft of row m.
- `draft(k)` with fusion: draft 2 comes from g and draft 1 (host input, after
  the sync). Each later draft takes the previous forward's norm row and
  argmax on the device, embedded from the draft rows (row i of the head's
  projection is the embedding of draft ID ids[i]). There is one sync for
  all of them.
- Syncs per verify pass: 1 for k = 1 and 2 for k >= 2 (were 1 + k).
  `DeviceDraft::set_fused(false)` and `--no-fused-draft` restore the ADR
  0028 path for comparison.
- Fused drafts are bitwise the same as unfused ones. The head's input
  values are the same, and the head runs the same kernels for every row
  count it sees (1-4 rows: the fixed GEMVs and the per-row decode attention
  of ADR 0024/0026). `device_real_speculative` checks the generated IDs and
  that the passes and acceptances of fused and unfused runs are equal.

## Consequences

M5, the 8 prompts, 128 new tokens.

`metal-infer` (first 4 prompts, twice): 73.3-73.6 -> 75.2-75.8 tok/s
including the selection, with the same generated IDs. `metal-chat`
snapshots (a 48-token turn, then a 32-token turn after loading it) are
byte-identical to the previous build.

Speculative decoding, device draft, 8,192 rows, plain baseline with the
device argmax (75.2-76.9 tok/s), medians of 2 runs:

| depth | unfused (ADR 0030) | fused | draft ms/pass | verify (+ absorb) ms/pass |
|---|---|---|---|---|
| 1 | 1.46x | 1.51x | 1.10 -> 0 | 13.3 -> 14.0 |
| 2 | 1.61x | **1.63x** (123.6 tok/s) | 2.07 -> 1.22 | 13.6 -> 14.2 |
| 3 | 1.59x | **1.64x** (123.5 tok/s) | 2.90 -> 1.82 | 13.95 -> 14.6 |

- The absorb now costs about 0.6 ms inside the verify pass's stream. As a
  separate forward with its own sync it cost about 1.1 ms.
- A chained draft still costs about 0.9 ms of GPU time with no sync. So the
  rest of the head's cost is on the GPU, not in syncs. It is about 20
  dispatches over small matrices (1024 x 1024 to 3584 x 1024, 41 MB in all,
  plus 16.8 MB of draft rows), which do not reach the bandwidth of the main
  model's large matrices.
- Depths 2 and 3 are now equal within noise (1.63 / 1.64x).
- ROCm: `qr_argmax` is absent, so infer, chat and the speculative loop take
  the host paths as before.

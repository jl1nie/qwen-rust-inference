# ADR 0025: MTP drafts over a subset of the vocabulary; acceptance on CPU

Status: accepted (measurement; speculative decoding itself is not built).
See spec/measurements/mtp-draft-vocab-cpu.json, ADR 0022-0024 and spec/roadmap.md item 3.

## Context

A full MTP draft reads the 41 MB head plus the 509 MB vocabulary projection,
about 0.37 of a decode step (1.50 GB). After ADR 0024 a verify pass of 2-7
tokens costs 1.05-1.10 decode steps at a 454-token context. With the full
vocabulary, speculative decoding then reaches only about 1.07x (ADR 0024).

A draft can use fewer rows of the projection. The main model still checks
every drafted token over the full vocabulary, so the output stays the same.
Only the acceptance rate drops: a token outside the subset can never be
drafted.

## Decision

- `mtp::DraftVocab` (src/mtp.rs) gathers the embedding rows of a sorted ID
  list into its own BF16 matrix. `argmax` projects onto it; ties go to the
  smaller ID, as in greedy.
- `MtpWeights::step_hidden` returns the head's normalized output without a
  projection; `step` = `step_hidden` + the full projection.
- `mtp-accept --draft-vocab 0,N1,N2,...` measures several subsets in one
  greedy run (0 = full); each subset chains its own drafts.
  `--draft-vocab-text PATH` orders the tokens by their frequency in that
  text, then by ID. Without it the order is by ID (BPE merge order). The
  EOS IDs are always included. It also reports the coverage: the share of
  generated tokens that are in the subset, an upper bound on draft 1.
- `tests/mtp.rs`: a subset's argmax equals the full argmax restricted to it.

## Consequences

M5 CPU, the 8 prompts of ADR 0022, 128 greedy tokens each, 851 drafting
positions. "Accepted up to j" for drafts 1/2/3, tokens per verify pass with
3 drafts, and coverage:

| subset | order | drafts 1 / 2 / 3 | tokens/pass (k=3) | coverage |
|---|---|---|---|---|
| full (248,320) | — | 68.4 / 43.2 / 26.8 % | 2.38 | 100 % |
| 32,768 | token ID | 54.9 / 31.1 / 18.1 % | 2.04 | 71.5 % |
| 65,536 | token ID | 56.2 / 32.4 / 18.9 % | 2.07 | 74.6 % |
| 32,768 | docs (spec/*.md) | 61.9 / 35.3 / 20.7 % | 2.18 | 84.7 % |
| 32,768 | model corpus | 62.4 / 36.2 / 21.6 % | 2.20 | 85.3 % |
| 4,096 | model corpus + docs | 59.6 / 34.2 / 20.4 % | 2.14 | 79.0 % |
| 8,192 | model corpus + docs | 62.7 / 37.2 / 22.4 % | 2.22 | 85.4 % |
| 16,384 | model corpus + docs | 63.9 / 38.2 / 22.9 % | 2.25 | 88.8 % |
| 32,768 | model corpus + docs | 64.6 / 38.6 / 23.1 % | 2.26 | 90.7 % |

- The ID order works poorly: Japanese tokens have high IDs, and 28 % of
  the generated tokens fall outside the first 32k IDs.
- Frequency in a small sample of text works much better. The "model corpus"
  is 8,544 tokens that the model itself wrote (Metal, greedy) for 24 other
  prompts (spec/measurements/mtp-vocab-prompts.txt, -corpus.txt). Adding
  spec/*.md helps a little more.
- The drop from the full vocabulary is about 4-6 points on draft 1. Without
  the full projection, a CPU draft step takes 0.6-1.2 ms instead of 5.3 ms.

Estimated speedup on Metal (verify ratios of ADR 0024, draft cost = (41 MB +
N x 2 KB) / 1.50 GB, checkpoint every pass, restore on rejection; not
measured end to end), model corpus + docs order, k = 1 / 2 / 3:

| context | full | 8,192 | 16,384 | 32,768 |
|---|---|---|---|---|
| 454 | 1.07 / 1.07 / 1.01 | 1.30 / 1.51 / 1.61 | 1.30 / 1.50 / 1.59 | 1.28 / 1.46 / 1.53 |
| 2644 | 0.97 / 1.00 / 0.96 | 1.16 / 1.36 / 1.48 | 1.16 / 1.36 / 1.47 | 1.14 / 1.32 / 1.41 |
| 8192 | 0.84 / 0.89 / 0.87 | 0.97 / 1.15 / 1.26 | 0.97 / 1.15 / 1.25 | 0.97 / 1.13 / 1.21 |

With these numbers, 8k-16k rows and 3 drafts are the best choice: about
1.6x at short contexts and 1.25x at 8192 tokens. The rest of the gap at long
contexts is the attention step of ADR 0024.

Caveats:
- The corpus comes from the same model on other prompts, and the 8
  evaluation prompts are few. Other kinds of text (other languages, long
  code) may be covered less well.
- Sampling is not measured (greedy only).

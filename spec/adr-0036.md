# ADR 0036: GPTQ recovers most of the 4-bit loss, not all

Status: study, recorded. No 4-bit format or kernel is added. See
spec/measurements/cuda-rtx4060-gptq-study.json.

## Context

ADR 0035 showed that round-to-nearest (RTN) 4-bit weights are far from
int8. The best grid tried (affine, groups of 32, 5.0 bits per weight) is
+8.6% perplexity, against +0.6% for int8. Per-row 4-bit nearly triples
perplexity. GPTQ (Frantar et al., 2022) picks the rounding with data. It
rounds a matrix column by column, and spreads each column's error over the
columns not yet rounded. The weighting uses the inverse Hessian
H = Xᵀ X of the projection's inputs, so the outputs X Wᵀ change as little
as possible.

## Method

`gpu_gptq_study` (src/device/tests.rs, ignored). It uses the evaluation of
ADR 0035 (`QualityStudy`, now shared by both studies): README.md, a
32-token prompt, then 512 positions, compared with BF16.

**Calibration.**
- The BF16 model runs 1,024 tokens of spec/learning.md, metal.md and
  rocm.md, a different text from the evaluation.
- With `capture` on, it records the input of every projection:
  - `input_norm`: q/k/v, DeltaNet qkv/z/a/b;
  - `post_norm`: gate/up;
  - `ffn_product`: down;
  - `mixer_core`: o/out (new, kept apart in `DeviceStep::projection_inputs`
    so the CPU checks and traces see the same records as before);
  - the final norm: the vocabulary projection.
- There is one Hessian per distinct input. Projections that share an
  input share it.

**GPTQ** (`gptq`, `gptq_inverse`):
- H gets 1% of its mean diagonal added. U is the upper Cholesky factor of
  H⁻¹ (f64, then f32).
- Columns are processed in blocks of 128. Inside a block, each column's
  error `(w − q) / U[i][i]` updates the later columns of the block. After
  the block, one matrix product updates the rest.
- Group scales are taken from the updated weights at each group start.
- Same grids and round-half-even as ADR 0035.
- Simplifications against the paper:
  - inputs come from the BF16 model, not sequentially through already
    rounded layers;
  - no act-order;
  - 1,024 calibration tokens instead of 128 × 2,048.

**Tests.**
- `gptq_matches_round_to_nearest_without_correlations`: with H = I, GPTQ is
  RTN.
- `gptq_lowers_the_output_error`: correlated inputs, output error below
  half of RTN's.
- `gptq_inverse_is_the_damped_inverse_factor`: Uᵀ U (H + damp I) = I.

The RTN rows of this study reproduce ADR 0035 to every reported digit.

## Results (BF16 perplexity 25.41)

| grid | bits/weight | top-1, RTN → GPTQ | KL mean | perplexity |
|---|---|---|---|---|
| int4 sym row | 4.0 | 45.5 → 66.4% | 1.15 → 0.47 | 71.92 → 39.84 |
| int4 sym g128 | 4.1 | 67.4 → 75.2% | 0.41 → 0.20 | 39.92 → 28.80 |
| int4 sym g64 | 4.3 | 69.7 → 81.1% | 0.30 → 0.14 | 35.91 → 28.74 |
| int4 affine g64 | 4.5 | 76.2 → 83.2% | 0.18 → 0.10 | 30.53 → 28.88 |
| int4 affine g32 | 5.0 | 81.8 → 87.1% | 0.13 → 0.06 | 27.59 → 26.94 (+6.0%) |
| int8 sym row, RTN (ADR 0034) | 8.0 | 96.3% | 0.002 | 25.57 (+0.6%) |

1. **GPTQ helps on every grid.** It roughly halves the mean KL. Even
   per-row 4-bit comes back from 72 to 40.
2. **GPTQ with fewer bits beats RTN with more.** sym g128 (4.1 bits) gives
   28.8, against RTN sym g32 (4.5 bits) at 32.3.
3. **sym g128, sym g64 and affine g64 all land at 28.7–28.9.** Finer
   scales stop helping there, so another limit dominates. It may be the
   small calibration set or the non-sequential inputs; this was not
   measured.
4. **The best result is +6.0%** (affine g32, 5.0 bits). The gap to int8's
   +0.6% stays large.
5. **The tails can get worse.** The worst position's KL rises for sym g64
   (2.35 → 3.53) while the mean halves.
6. **Residual error by position flips.** With RTN, the later position had
   the larger per-layer residual difference (sym g64: 26% → 34%). With
   GPTQ it is the smaller (24% → 20%). The growth seen with RTN in ADR 0035
   is therefore not a fixed property of the DeltaNet state. As before, two
   positions cannot settle it.

**Time** (host CPU, 8 threads):
- capture: 25 s;
- Hessian inverses: 454 s (plain f64 loops; the 3,584-dim FFN input
  dominates);
- GPTQ: 21–33 s per grid, including the vocabulary projection.

## Decision

No 4-bit format yet. The study, its tests and the `mixer_core` capture
stay.

GPTQ is the right direction for 4 bits on this model, but at +6% it is not
yet close enough to int8 to justify 4-bit kernels. The next measurements
to make, each cheap with this harness:

- sequential GPTQ;
- more calibration tokens;
- act-order;
- an error curve over positions, for the DeltaNet question.

## Limits

One evaluation text, close in kind to the calibration text (both are this
repository's documents). Rounding error only: no 4-bit kernels, no speed.
FP32 scales in the study.

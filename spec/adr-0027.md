# ADR 0027: greedy speculative decoding end to end (Metal verify, CPU MTP draft)

Status: accepted (first end-to-end version; the draft still runs on the CPU).
See spec/measurements/metal-m5-speculative.json, ADR 0022-0026 and
spec/roadmap.md item 3.

## Context

ADR 0026 made a verify pass of 2-4 rows on Metal bitwise equal to decoding
the same tokens one at a time, and added a rollback (`verify_rollback` /
`accept`) through per-token DeltaNet snapshots. What was missing was the
loop itself: the MTP head needs the main model's final-normalized hidden
state h_i of every position (ADR 0022), and the device run returned only
logits.

## Decision

- `DeviceRun::set_capture_hidden(true)`: every forward (prefill chunk, step,
  verify) also norms all of its rows with the final norm and appends them;
  `take_hidden()` returns them in position order. The readback comes after
  the logits readback where it can: read before the vocabulary projection it
  split the command stream and cost about 0.5 ms for 4 rows.
- `device::speculative::generate` (src/device/speculative.rs), greedy only:
  1. prefill the prompt with hidden rows; the first token is the argmax;
     the MTP head absorbs the true pairs (h_i, s_{i+1}) of the prompt;
  2. draft k tokens: the first from the last true pair, then the chain of
     ADR 0022; the chain's KV rows of the head are cut afterwards;
  3. `verify_rollback([cur, d1..dk])`; m = the leading drafts equal to the
     main model's argmax; `accept(m + 1)`; emit d1..dm and the argmax of row m;
  4. the head absorbs the m + 1 new true pairs from the verify pass's hidden
     rows.
  Every emitted token is the main model's own argmax, so the output equals
  plain greedy as long as verify rows equal decode steps (on Metal: depth <= 3).
- The draft runs on the CPU engine (`MtpWeights::step_hidden`, `DraftVocab`).
- `<engine>-speculative` runs plain greedy and speculative decode on the
  same device for every prompt and compares the IDs and the decode time.
  `mtp::frequency_order` is the token order of `--draft-vocab-text`, shared
  with `mtp-accept`.
- `device_real_speculative`: the IDs equal plain greedy for the full
  vocabulary and a 4096-token subset at depths 1 and 3; prefill hidden rows
  equal those of single steps.

## Consequences

M5, the 8 prompts of ADR 0022, up to 128 new tokens (851 decoded tokens),
decode phase only. The IDs equal plain greedy in all 9 runs.

- The best setting is 8,192 rows and 2 drafts: 1.40x, below the 1.75x that
  ADR 0026 estimated. Three things the estimate left out:
  - The CPU draft: 1.9-3.7 ms per pass (0.14-0.27 decode steps). Besides
    the k drafts it also absorbs the m + 1 true pairs, 1-4 more head steps
    per pass. On the GPU a head step reads 41 MB (~0.03 decode steps).
  - A verify pass in the loop costs 1.12-1.22 decode steps, against
    1.00-1.08 in `metal-verify`: the argmax of every row on the CPU (~0.4 ms
    for 4 rows) and about 0.6 ms more GPU time, probably because the GPU
    idles during the CPU draft.
  - The acceptance at the start of a pass is 2-6 points below the
    acceptance over all positions of ADR 0025 (8,192: 60.9 vs 62.7 % for
    draft 1). Passes start right after a rejected draft or after a run of
    accepted ones, which are not average positions.
- The full vocabulary is slower than plain decode on the CPU (5 ms per
  projection), as ADR 0024 predicted.
- The MTP head over the prompt takes 16-27 ms on the CPU for these short
  prompts (reported as `mtp_prompt_s`, not in the decode time); it grows
  with the prompt length.
- ROCm has no snapshots yet, so `rocm-speculative` stops at
  `new_run_rollback`.

Next: the MTP head and the draft projection on the GPU, which should remove
most of the draft cost (estimated about 1.5-1.65x for 8,192 rows, k = 2-3;
not measured), and the argmax of the verify rows on the GPU.

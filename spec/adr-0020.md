# ADR 0020: per-head SIMD kernels and grouped decode projections (Metal)

Status: accepted; passed on Apple M5 (macOS 27.3). Ideas taken from ROCm's
ADR 0019, items 1-2. See spec/measurements/metal-m5-decode-small-kernels.json.

## Context

ADR 0019 made ROCm decode 1.9x faster. Most of its items address GEMVs that
reached only 30-60 % of the memory bandwidth. Metal's GEMVs already run near
the limit (ADR 0009), so those items do not apply here. A per-dispatch
decode profile at 2644 tokens (64 tokens minus 1, one command buffer per
dispatch) put about 2.5 of 18.8 ms outside the GEMVs. The largest part was
three level-1 kernels that use one thread per head:

| kernel | per call | calls/token | per token |
|---|---|---|---|
| attention_kv (2 threads) | 74 us | 6 | 0.45 ms |
| delta_qk (16 threads) | 23 us | 18 | 0.42 ms |
| attention_query (8 threads) | 58 us | 6 | 0.35 ms |

The 16-row DeltaNet a/b GEMVs took about 10 us each (36 calls per token),
launch-bound rather than bandwidth-bound.

## Decision

1. Level-2 `delta_qk_simd`, `attention_query_simd`, `attention_kv_simd`
   (elementwise.metal; ADR 0019 item 1):
   - One SIMD group per (token, head); the sums of squares are SIMD
     reductions.
   - Every output element is the level-1 expression computed by one lane.
   - The RoPE pair (i, i + rot/2) is normalized and rotated by one lane.
   - Only the order of the norms' sums changes. Level 1 keeps the
     one-thread kernels (`--metal-kernels reference`).
2. Optional `qr_gemm_bf16_group` in the Metal bridge (ADR 0019 item 2; the
   Rust engine already calls it when a bridge exports it):
   - For fewer than 8 tokens, up to 4 BF16 matrices that read the same X
     (DeltaNet qkv/z/a/b, attention q/k/v, FFN gate/up) run in one dispatch
     of `gemv_bf16_group`, matrix after matrix.
   - Each row runs `gemm_rows`, the gemv_bf16 code, so the outputs are
     bitwise equal to separate calls.
   - Prefill chunks keep one `run_matmul` per matrix (tiled / tensor
     kernels).

Not taken from ADR 0019:
- More GEMV loads in flight and one-token GEMV kernels (Metal GEMVs already
  stream near the limit).
- Decode attention without staging (ADR 0017 already reads K/V directly).
- HIP-specific fused tails.
- Fused add + norm and GLU: a Metal dispatch costs about 0.5 us against
  ROCm's 2.5 us, and the earlier GLU fusion gave nothing (ADR 0009). Left
  for later measurement.

## Consequences

M5, BF16, default level (tensor), 64 new tokens:

| prompt | decode before | after |
|---|---|---|
| 454 | 69.1 tok/s | 74.2-75.3 |
| 2644 | 67.5 | 69.8-72.6 (median of 5 runs: 72.3) |
| 10141 | 60.5 | 61.3-64.8 |

- The per-head kernels give nearly all of it. Without the grouped
  projections, 2644 tokens decode at 71.1-71.3 tok/s and 454 at
  73.9-74.3. The grouping adds +0.5 to +1.3 tok/s, within run-to-run noise,
  and is bitwise neutral (same prefill top-5 logits with and without it).
- Prefill is slightly faster (2644 tokens: 1.226 -> 1.197 s).
- Generated tokens are unchanged on all prompts.
- `device_real_kernel_levels` compares level 1 (one-thread kernels) with
  levels 2 and 3 (SIMD-group kernels) on real weights.

# ADR 0008: position-split decode attention

Status: experimental; passed on Apple M5 (macOS 27.3), Metal engine. ROCm is
unchanged (it ignores the new hint). See
spec/measurements/metal-m5-decode-split.json. CPU reference remains the
oracle and ADR 0004 tolerances are unchanged.

## Context

After ADR 0007 decode (T = 1) still used the 3-pass read: a softmax with one
threadgroup per head and a weighted sum with one thread per (dim, head) that
loops over all L positions. At 10141 tokens decode fell to 29 tok/s vs 50 at
short contexts.

## Decision

Metal decode uses flash-decoding: `attention_split` runs one threadgroup per
(block of B positions, KV head) with one SIMD group per query head sharing
that KV head, an online softmax over its block, and writes the partial
(max, denominator, unnormalized head_dim sums) to scratch.
`attention_combine` (one thread per (dim, head)) rescales the partials by
exp(m_s - M), divides, and applies the sigmoid gate.

- B = 32 positions (`ATTENTION_SPLIT` in Rust, `kSplitSpan` in bridge.mm),
  grown only if the scratch cannot hold the splits. Measured on M5: B = 128
  cost short-context decode (45.6 vs 50 tok/s, too few threadgroups); 32 and
  64 were equal at 10k tokens, 32 better at 454.
- Scratch reuses the attention score buffer, enlarged per head to
  `max(capacity, ceil(capacity/32) * (head_dim + 2))` floats (about 1.5 KiB
  per token over the 6 layers vs about 24 KiB of KV) and passed as
  AttentionRead slot n6. n6 is only a hint, so the ABI stays v3: a library
  that ignores it (ROCm, CPU bridge) still computes the 3-pass result with
  the score row at stride n4. The 3-pass Metal read remains the fallback for
  n6 = 0 or head_dim > 512.
- The summation order changes vs the 3-pass read (ADR 0004 tolerances).

## Consequences

M5, BF16, chunk 128, 64 new tokens, single runs: decode 29.3 -> 40.1 tok/s
at 10141 tokens, 43.2 -> 47.9 at 2644, 45.8 -> 48.9 at 1666, unchanged at
454 (50 tok/s). First 16 generated tokens identical to the ADR 0007 runs.
Real-weight check max error 1.97e-4 and the 2048-token long check 3.2e-4,
both unchanged. Not done: fused kernels, fewer command-buffer syncs, ROCm.

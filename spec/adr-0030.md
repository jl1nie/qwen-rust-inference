# ADR 0030: greedy picks on the device (Metal)

Status: accepted. See spec/measurements/metal-m5-device-argmax.json and
ADR 0028.

## Context

In the speculative loop of ADR 0028, a verify pass read the logits of every
row back to the host: 248,320 floats (~1 MB) per row. `read_prefix` checked
them for non-finite values, and `generate::select` checked them again and
took the argmax. A pass of 3 rows took 14.54 ms against a decode step of
13.5 ms. Plain greedy decode pays the same cost for its single row.

## Decision

- Bridge op 16 `Argmax` (`argmax_rows`, norm.metal), advertised by the
  optional symbol `qr_argmax` and not by `qr_max_op`: op 15 is HIP's fused
  `AttentionQueryKv`, which the Metal bridge does not build, and
  `qr_run` now refuses it. There is one threadgroup per row. Each thread
  scans the row in increasing index order and keeps the first maximum, then
  a SIMD and threadgroup reduction takes the largest value with ties to the
  smaller index. This is the rule of `generate::select` with greedy
  sampling. The kernel writes [index, number of non-finite values] per row,
  and the host refuses the row unless the count is 0 (select refuses
  non-finite logits too).
- `DeviceRun::verify_rollback_greedy(ids)` and `step_greedy(id)` return the
  token IDs and read back only 2 floats per row. Without `qr_argmax` (HIP,
  the CPU test bridge) they read the logits and use `select`, so the result
  is the same.
- `speculative::generate` uses `verify_rollback_greedy`.
  `<engine>-speculative --plain-device-argmax` makes the plain baseline use
  `step_greedy`. By default the baseline still reads the logits, as
  `<engine>-infer` does.
- Tests: in `device_real_rollback`, `verify_rollback_greedy` for 2-8 rows
  equals `select` over the logits of `verify_rollback`. In
  `device_real_speculative`, `step_greedy` generates the same IDs as `step`
  + `select`.

## Consequences

M5, device draft, 8,192-row draft vocabulary, the 8 prompts of ADR 0022, 128
new tokens. Medians of 2 runs, tok/s. The IDs equal plain greedy in every
run. The plain baseline is shown both ways:

| depth | plain (host argmax) | plain (device argmax) | speculative | speedup vs host / device baseline | verify ms/pass (ADR 0028) |
|---|---|---|---|---|---|
| 1 | — | 76.0 | 111.7 | — / 1.47 | 13.29 (14.13) |
| 2 | 73.5 | 75.8 | 121.9 | 1.66 / 1.61 | 13.60 (14.54) |
| 3 | 73.2 | 75.4 | 120.6 | 1.65 / 1.60 | 13.92 (15.20) |

- A verify pass is about 1 ms shorter. It now costs about the same as a
  decode step that reads its logits (13.6 ms for 3 rows, 13.9 ms for 4).
  The 1 ms was the readback of the logits and two host passes over them,
  not the argmax alone (estimated at 0.4 ms).
- Plain greedy with the device argmax goes from 73.5 to 75.8 tok/s (13.6 ->
  13.2 ms per token). Against that fairer baseline, speculative decoding is
  1.61x with 2 drafts. Against the baseline as `<engine>-infer` runs today,
  it is 1.66x.
- The values are unchanged: only where the argmax is taken changes, and the
  rule is the same. `<engine>-infer` / `-chat` still read the logits (they
  sample, trace and report top-5). Using `step_greedy` for their greedy path
  is a separate change.
- ROCm has no `qr_argmax` yet and falls back to the host.

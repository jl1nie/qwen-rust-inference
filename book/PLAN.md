# 執筆計画｜Rustで学ぶLLM推論

[執筆・検証・組版の実日計画](EXECUTION-PLAN.md)に、見開きごとの頁割り、作業日、確認版の条件を示す。

## この本で答える問い

QwenのFFNの重みを一列変えると、どの計算が変わり、次に出るトークンにどう影響するのか。着想は [Weight-Space Programming](https://rikiyat.github.io/blog/weight-space-programming/) の重み介入実験にある。上巻では、まずCPU上で1トークン分の値と状態を追い、最後に重みを変えて差を観測する。下巻では、同じ計算をGPUに載せたとき、どのデータを何度読み、どこで同期し、速くした結果が参照実装と合っているかを確かめる。

## 読者と説明の順序

読者は、Rustの配列、添字、ループを読めて、LLMが出力を選ぶ仕組みに興味のある人。機械学習、Transformer、線形代数、GPUカーネルは初出箇所で説明する。上巻の合成例には実モデルの重みやGPUを要しない。下巻のGPU実測は、手元で実験する場合と保存ログを読む場合の両方を案内する。

各節は、疑問 → 小さな具体例 → 数式とRustの対応 → 実モデルまたは実装での照合、の順を基本にする。新しい用語を出すときは、何を入力にして何を出力するかを先に示す。模型で省く演算や、測定の条件を明記する。読後の確認では、読者が例の数値や入力形状を一つ変えて、結果を予想できるかを見る。

## 上巻｜Qwenの1トークンをCPUで追う

上巻は全巻の基礎編。下巻で前提にする概念を初出から丁寧に扱う。位置とID、行列の形、内積、丸め、状態更新、データ移動の見積もりは、それぞれ小さな入力、途中値、対応するRustの添字まで示す。下巻はGPU固有の実行モデルや道具を使う箇所で導入し、共通の計算は上巻の章・節へ戻れるようにする。

### 第1章　Qwenが「東京」を出すまで（12頁）

- 質問だけの文字列と会話テンプレート適用後の文字列を並べる。UTF-8のバイト列、小さなBPEの結合規則、固定モデルの実IDの順に追い、復号で文字列へ戻る。
- 小さな埋め込み表でIDから行を引く。位置とIDと層を分け、内積でlogitsを作り、greedyで選んだIDを次の入力へ渡す。
- 同じ生成記録で「東京」を予測した位置と「東京」を入力した位置を指せるか確認する。Attention図は位置を読む入口にし、重みの計算は第2章、生成への影響は第3章で調べる。

### 第2章　Transformerのブロックを手で計算する（30頁）

- **15–21頁、位置内の変換。** ブロック全体の入出力を示し、残差とRMSNormを手で計算する。FFNではgate・upからSiLUと要素積を経てdownへ進む。中間成分とdownの一列を掛けた値が残差へどう届くかをRustの添字と対応させる。
- **22–37頁、位置をまたぐ状態。** 2位置でQ/K/V、因果マスク、RoPE、softmax、GQAを順に追う。逐次実行と一括処理を照合する。次にDeltaNetの畳み込み履歴と再帰行列を2位置分更新する。36–37頁の見開きで、AttentionのK/Vの追記とDeltaNetの状態更新を並べる。
- **38–44頁、実モデルの24層。** どの層がどちらの状態を持つかを示し、同じ位置のmixer出力とFFN出力が残差を更新する経路をトレースで読む。演習では、次の1位置を入力したときに、どの配列が更新されるかを予想する。

### 第3章　CPUで確かめ、重みに介入する（16頁）

- **45–51頁、計算の照合。** 重み、活性値、状態の寿命を区別する。行優先の参照ループとBF16の丸めを小例で読み、手計算、固定fixture（テスト用の固定データ）、上流実装との実重み比較で、それぞれ何が確かめられるか示す。固定した層・位置・演算名で、最初にずれた中間値を探す。
- **52–56頁、計算量とデータ移動。** FFNのgate射影（重み3,584行×1,024列）を1位置と128位置で使い、積和の回数と重みのバイト数を数える。帯域から出した見積もりの前提を明記し、下巻のprefillとdecodeへ渡す。
- **57–60頁、重み介入。** 第2章で扱ったdownの一列を使い、ある方向の成分を係数1・6で引いた結果を手計算する。実Qwenでは未編集と編集ありに同じ入力を与え、介入した層のFFN出力、残差、同位置のlogits、greedyで選ぶIDの順に照合する。生成が分岐した後の文章は別に示す。
- 公開された編集との差を、元モデルの版、層・列、係数、BF16丸めの位置から調べる。小例、Rustの介入結果、公開差分との数値照合、記事の評価値を区別する。掲載する結論は取得できた結果に合わせる。

## 下巻｜QwenをMetalで速くする

「Metal」はAppleのGPU向けAPIと、実際に計算するGPUというハードウェアの二つを指す。Apple Siliconを主軸に、実装と測定の読み方をAMDとNVIDIAにも広げる。章番号は上巻から引き継ぐ。

| 章 | 本文で追う順序 | 読者が確かめること |
|---|---|---|
| 4. 重みを使い回す ― Metalのprefill | 第3章と同じgate射影を128位置で出発 → 出力タイル、ロード、同期、書き戻し → SIMD group・Metal 4 → online softmaxとDeltaNetの位置依存 | タイルが担当する出力と再利用する重みを指す。2分割したsoftmaxが、一括で計算した値に合うか確かめる。 |
| 5. 重みを読み切る ― Metalのdecode | 同じgate射影を1位置にする → BF16の1行をlaneで分担 → 長文脈のK/V読み出し → 発行・同期・融合 | 重みとK/Vのバイト数をそれぞれ数え、帯域の見積もり、カーネル計時、1ステップ全体の時間を照合する。 |
| 6. 1回の検証で複数トークンを進める ― MTP | 下書き → 2〜4行をまとめて検証 → 採用境界 → AttentionとDeltaNetの状態復元 → 時間収支 | 採用した出力IDと、状態に反映済みの入力IDを区別する。上巻の状態表を使い、次の1ステップを逐次実行と照合し、採用数と全体の時間から速度を求める。 |
| 7. ROCmで同じ推論を測る | wave内の分担 → 先行ロードとキャッシュ条件 → 発行計時 → 推論全体での通常decodeとMTP | AMDの単体GEMVと推論全体の計時を区別し、先行ロードやMTPが効いた条件を記録から説明する。 |
| 8. CUDAで同じ射影を組む | 同じ形のBF16 GEMV → warp内の部分和 → CPUで二重照合 → RTX 4060／WSL2でGraph・キャッシュ条件を変える → ROCmのカーネルをnvccでビルドした推論器 → CPU照合と速度 → 1ステップの内訳 | 前半は単体の射影の条件と、装置・発行方式・集計方法の違いを表で読む。後半はwarpのマスクの違い、推論器全体の照合と速度、投機的decodeの倍率と少数行の検証の費用（M5・ROCmとの比較）、CUDA Graphを採らなかった理由とargmaxの2段化を測定で示す。 |
| 9. 重みを減らす ― INT8と4ビット | decodeは帯域で頭打ち → 行ごとのスケールのINT8 → 融合を保って発行回数を戻す → CPU照合ではなく「何がどれだけ変わるか」で測る → 速度 → 囲み記事で4ビット | 値が変わる高速化を、正解のトークンを入力にした比較（最上位の一致、KL、perplexity、層ごとの差）で評価する。4ビットは結論と表1つにとどめ、GPTQの中身はADR 0035・0036を参照する。 |
| 付録. コードと測定を再現する | 実装とモデルの版を固定し、3環境のコマンドと保存ログをたどる | 各章が根拠にした測定の条件とログを探せる。 |

下巻の巻き戻し見開きでは、上巻36–37頁の状態表と同じ記号を使う。Metalの行列積の試作は8頁。

## 上巻が下巻に渡すもの

| 上巻で計算できるようにすること | 下巻でその計算を使う場面 |
|---|---|
| FFNの同じ行を、1位置と複数位置の入力に適用する | prefillのGEMMで重みを再利用し、decodeのGEMVと比較する |
| Attentionが位置ごとのK/Vをどう読むか、DeltaNetが何を更新するかを区別する | 長文脈のKV読み出しと、投機的デコードでの巻き戻しを説明する |
| BF16行列のバイト数と、積和の回数を別々に数える | 実行時間の目安と実測を突き合わせ、演算器・帯域・発行の費用を比較する |
| 小さな配列と実モデルで、数値と状態を照合する | 実行経路を変えた後に、形・精度・生成ID・採用後の状態を確認する |

## 試作で得た紙幅と残りの作業

A5・左綴じの現時点の原稿は、上巻39頁、下巻61頁（第8章にCUDAの実測を入れて8頁、第9章の量子化を5頁）。現行の改ページを使った組版結果。第7・8章を独立させる前の原稿で、テンプレートを仮適用した本文11ptの比較組版は上巻31頁、下巻34頁だった。BPE、FFN、DeltaNet、演算量と帯域の小例を上巻へ追加した。上巻ではFFNの一列を編集する手計算を試作した。次稿ではCPU fixtureの比較、同一入力での実モデルへの介入と公開差分の照合を深める。下巻ではGEMVとMTPの計算例を深める。その後、重複を整理し、必要な図と演習に紙幅を配分する。

- 上巻は、現状の手計算を合成fixtureおよび実モデルのトレースに接続する。初見の読者が、入力を変えたときのID列や、1位置追加時の状態を予想できるかを確認する。
- 下巻はBF16 GEMVのlane割り当て、長文脈のKV読み出し、MTPの速度収支を具体化する。手計算と保存ログから読者が結論を再現できるかを確認する。

# 執筆計画｜Rustで学ぶLLM推論
## Qwenの1トークンを、数式からGPUカーネルまで

技術書典向けの本文・前付け・付録68頁、表紙別。仮判型はA5・左綴じ。頁は完成稿の設計値。偶数頁と次の奇数頁を見開きとして扱う。

Qwen3.5-0.8Bを参照アーキテクチャにし、現代の推論エンジンで使われる設計を、数式・状態・実装・ハードウェアの順に追う。Rustのループと配列を読める人を想定する。内積、テンソルの軸、Transformer、Metalは使用箇所で導入する。合成重みのCPU演習と、実モデル・GPUの測定ログを用意する。

同じFFN射影を第2・3・4・5章で、同じAttention／DeltaNetの状態例を第2・6章で使う。読者が予想し、それをコード、数値または測定で確かめるところまで書く。

## 前付け｜1–2頁

1頁に書名と本書で追う問い。2頁に目次、想定読者、CPUデモと保存ログで進める経路、Apple Siliconで再現する経路を載せる。掲載コードの版と実行手順は68頁に集約する。

## 第1章　Qwenが「東京」を出すまで｜3–8頁

到達点は、入力末尾の位置が次のIDを予測し、選んだIDが次のステップの入力になることを説明できること。

| 頁 | 書く内容と誌面 |
|---|---|
| 3 | 質問「日本の首都はどこですか？一言で。」と実行結果。読者に「最初の応答を決めたのは入力列のどの位置か」を問う。 |
| 4–5 | 実トレースのトークン列を抜き出し、会話テンプレート由来の位置、入力末尾、最初の応答トークンを色分けする。位置×層の図と最初のAttention層のヒートマップを並べ、行・列・重みの見方を示す。掲載時にNDJSONとトークン列から「東京」の境界・予測位置を照合する。 |
| 6–7 | IDを添字として埋め込みの行を引く。2要素の内積を計算し、候補スコアを作る。実装へ戻って隠れ幅1,024とlogitsの語彙軸を示す。本文ではgreedyを1回だけ手計算する。 |
| 8 | `Model::step_hidden` の骨格を抜粋し、埋め込み → 24層 → 最終正規化 → 語彙射影の順に注釈する。演習は「予測する位置と、予測されたIDが入力になる位置を図に記す」。 |

参照元は `src/model.rs`、`src/generate.rs`、`spec/tensors.md`、`spec/images/attention-layer3.svg`。

## 第2章　Transformerのブロックを手で計算する｜9–18頁

到達点は、各位置の計算と、トークン間で持ち越す状態を区別できること。

| 頁 | 書く内容と誌面 |
|---|---|
| 9 | `block.rs` をもとに1ブロックを描く。正規化したベクトルを演算に渡し、結果を残差へ加える流れを2回たどる。Qwenでは最初の演算がAttentionまたはGated DeltaNetで、後段にFFNが続く。 |
| 10–11 | FFNを2成分の入力で計算する。`gate`・`up`・SiLU・要素積・`down` の形状を併記。中間ユニットを消したとき、`down` の対応列と活性値の積が消えることを手計算し、CPUテストと照合する。 |
| 12–13 | Q・K・Vの役割を2位置で説明する。内積からsoftmax、Vの重み付き和までを計算し、因果性とKVキャッシュを導入。GQAはどのQが同じK/Vを読むか、RoPEはどの時点でKを変換するかを小図にする。 |
| 14–15 | DeltaNetの更新を減衰 → 読み出し → 誤差 → ランク1更新 → 出力の順に書く。2行1列の行列で計算してから、短い畳み込み履歴と再帰状態が別々にあることを示す。小例で省いた処理は、実装の該当箇所を示す。 |
| 16–17 | `chapters/state-spread.typ` を育てる。AttentionはK/Vを追記、DeltaNetは状態を上書き。同じ値を入力した前後の状態を並べ、「この入力を取り消すと何を戻すか」を出題する。 |
| 18 | 幅8の合成モデルから実モデルに戻り、DeltaNet 3層＋Attention 1層の繰り返しを示す。演習はトレースでFFNの出力とトークン間の状態をそれぞれ指す。 |

参照元は `src/block.rs`、`src/ffn.rs`、`src/attention.rs`、`src/deltanet.rs`、`spec/learning.md`、`spec/exercises.md`。

## 第3章　Rustの参照実装を、GPU実装のものさしにする｜19–24頁

到達点は、何を比較すれば高速化後も計算が合っていると判断できるか、また重みをどこで再利用できるかを説明できること。

| 頁 | 書く内容と誌面 |
|---|---|
| 19 | 重み、実行中の状態、1ステップの活性値を、Rustの型と寿命で描き分ける。観測する経路から共通のブロック演算へ降りる。 |
| 20–21 | `[out,in]` の明示ループを行列式と照合。手計算、合成fixture、固定revisionの公式実装との比較の順に、どのレベルの不具合を見つけられるかを示す。 |
| 22–23 | FFNの `[3584,1024]` の重みを、入力1位置と128位置へ適用する。行列ベクトル積（GEMV）と行列積（GEMM）で重みの再利用がどう変わるか、配列の形とデータ移動で見せる。共有RustエンジンとMetalブリッジの境界も描く。 |
| 24 | 以降の測定の読み方を1頁に置く。ビット一致、許容誤差、生成ID、巻き戻し後の状態のうち、何を各実験で照合するかを提示する。演習は「logitsに小さな差があるが生成IDは同じ」という結果をどう報告するか。 |

参照元は `src/model.rs`、`src/device.rs`、`spec/tensors.md`、`spec/references.lock.json`、`spec/validation-real.json`。

| 頁 | 書く内容と誌面 |

| 28–29 | 参照カーネルと8×8 SIMD group行列演算を並べ、ロード・積和・書き戻しを追う。実装の主要部分を抜粋し、第3章のCPUループと同じ出力要素を指す。 |
| 30–31 | Metal 4の `matmul2d` へ。テンソルビューと演算器に渡すタイルを図にし、同一2,644トークンの3段階を計測条件付きで示す。 |

## 第5章　重みを読み切る ― Metalのdecode｜39–50頁

到達点は、帯域から速度の上限を見積もり、実測との差を小カーネル、KV読み出し、同期から説明できること。

| 頁 | 書く内容と誌面 |
|---|---|
| 39 | decodeの測定区間を定義する。生成トークン数と、測定に使った実際のdecodeステップ数を区別する。 |
| 40–41 | 重み約1.5 GBを出発点に、測定条件に対応する帯域から時間を見積もる。BF16 GEMVの1出力行をlaneで分担し、ロードと積和、集約がどこで起きるかを追う。 |
| 42–43 | Q/Kの正規化とRoPEを1ヘッド1スレッドから1 SIMD groupへ移す。演算本体の変化とカーネル発行の時系列を描く。プロファイルのための分割が実行時間に与える影響も扱う。 |
| 44–45 | 射影の一括発行と残差加算＋RMSNormの融合を比べる。DeltaNetの4演算をまとめても改善が測定のばらつきに収まった事例を扱う。 |
| 46–47 | 文脈が長くなるとKVがどれだけ増えるかを見積もる。GQAの複数QヘッドでK/Vを再利用し、位置をlaneへ割り振るMetalのdecode Attentionを追う。 |

| 50 | 演習は保存ログから重み帯域の目安を計算し、長文脈でずれる理由を説明する。次章への問いは「重みを一度読んで数トークンを確定できるか」。 |

| 54–55 | 少数行の検証を、通常decodeとprefillの中間に置く。2〜4行で各行にdecode Attentionを使う経路を図にし、長文脈での時間と逐次decodeとの照合を見る。 |
